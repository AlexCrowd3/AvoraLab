# AvoraLab — сайт студии

Реконструкция дизайна из Figma на React + Vite.

## Стек

- **React 18** + **Vite 5** — сборка и dev-сервер
- **react-router-dom** — переход между главной страницей и страницей "Услуги"
- **CSS Modules** — стили покомпонентно, без глобальных конфликтов
- **lucide-react** — иконки (имена символов в Figma-файле совпадают с иконками Lucide)
- **@fontsource/dm-sans** и **@fontsource/inter** — шрифты подключены локально (без внешних CDN, работает офлайн)

## Установка и запуск

```bash
npm install
npm run dev       # локальный сервер разработки (http://localhost:5173)
npm run build     # продакшн-сборка в папку dist/
npm run preview   # предпросмотр собранной версии
```

## ⚠️ Важно при деплое: настройка SPA-роутинга

Сайт теперь состоит из двух страниц (`/` и `/services`), переход между которыми происходит на
стороне клиента (React Router), без перезагрузки. При обычном клике по ссылке внутри сайта всё
работает из коробки. Но если открыть `/services` напрямую по ссылке или обновить страницу на ней,
сервер должен вернуть `index.html`, а не 404 — иначе React Router не успеет подхватить маршрут.

- **Netlify** — уже добавлен `public/_redirects`, ничего делать не нужно.
- **Vercel** — уже добавлен `vercel.json`, ничего делать не нужно.
- **Другой хостинг / nginx / Apache** — нужно настроить fallback на `index.html` для всех путей.
  Начиная с версии со страницами услуг сборка кладёт в `dist/` ещё и статические
  HTML-файлы для каждого адреса (`dist/services/landing/index.html` и т.д.), поэтому
  правило должно сначала отдавать существующий файл и только потом делать fallback:

  ```nginx
  location / {
    try_files $uri $uri/index.html /index.html;
  }
  ```

  Netlify и Vercel так делают по умолчанию: статический файл всегда отдаётся раньше,
  чем срабатывает правило `/* -> /index.html`.

## Структура проекта

```
src/
  App.jsx                — роутинг (react-router-dom)
  ScrollToTop.jsx         — прокрутка наверх/к якорю при смене страницы
  pages/
    Home/HomePage.jsx     — главная страница (весь прежний контент)
    Services/             — страница "Наши услуги": Hero + поиск с фильтром
  components/
    Header/               — шапка: лого, навигация (активный пункт зависит от маршрута), CTA
    Hero/                 — главный экран с мокапом телефона
    WhatWeBuild/          — секция "Что мы разрабатываем" (карточки услуг)
    WhyUs/                — секция "Почему с нами спокойно" (сетка преимуществ)
    PriceCalculator/      — интерактивный калькулятор стоимости (5 шагов)
    Process/              — секция "Прозрачный путь от идеи до запуска"
    Reliability/          — секция "Надежность на каждом этапе"
    FinalCta/             — финальный призыв к действию
    Footer/               — подвал сайта (лого, описание, соцсети, 3 колонки ссылок)
  styles/
    tokens.css            — все цвета, градиенты, радиусы, тени (дизайн-токены из Figma)
    global.css            — сброс стилей, базовая типографика, общие классы
  assets/images/           — изображения из Figma, сжаты в WebP
```

## Что стоит доработать дальше

- **Страница "Кейсы"** — в макете нарисован только один образец кейса, скопированный 6 раз с
  одинаковым текстом (явно как заглушка "тут будет сетка кейсов"). Чтобы страница не выглядела
  сломанной, я заполнил все 6 карточек разным содержанием — по одной на каждую услугу сайта. Как
  только у вас будут реальные кейсы, тексты и картинки стоит заменить на настоящие.

- **Страница "Услуги"** — в Figma нарисован Hero + поисково-фильтровая строка (3 состояния: обычное,
  выбран фильтр, панель фильтров раскрыта — я реализовал все три как рабочий интерактив), но самого
  списка услуг/карточек результатов в макете нет. Сейчас поиск и фильтр визуально работают
  (выделяют выбранный тип, показывают "Очистить фильтры"), но не выводят результаты — под них нужно
  либо добавить карточки услуг от вас, либо подключить реальный источник данных.
- **Навигация "Кейсы"** — в дизайне у неё пока нет отдельной страницы (только "Услуги" получила
  полноценную страницу), ссылка временно ведёт на секцию услуг на главной.
- **Калькулятор стоимости** — в Figma был нарисован только первый шаг ("Тип проекта"). Шаги 2–4
  (бюджет, сроки, доп. пожелания) и форма контакта — моё дополнение по аналогии, чтобы виджет был
  рабочим, а не просто картинкой. Тексты вопросов и вариантов стоит проверить/поправить под реальный
  процесс.
- **Формы (заявка, поиск услуг)** — сейчас работают только визуально/локально, никуда не отправляются.
  Нужно подключить реальный бэкенд/Telegram-бота/CRM.
- Ссылки-заглушки (`#contact`, соцсети в футере и т.д.) стоит проверить и связать с реальными
  адресами.


## Страницы услуг

Каждая услуга живёт по собственному ЧПУ-адресу и открывается кликом по карточке —
и на главной, и на странице `/services`:

| Адрес | Услуга |
| --- | --- |
| `/services/landing` | Лендинги и промо-сайты |
| `/services/online-store` | Интернет-магазины |
| `/services/web-service` | Веб-сервисы и личные кабинеты |
| `/services/telegram-bot` | Telegram-боты |
| `/services/mobile-app` | Мобильные и десктоп-приложения |
| `/services/express-development` | Экспресс-разработка |

Весь контент страниц услуг лежит в одном файле — **`src/data/services.ts`**. Вёрстка
(`src/pages/ServiceDetail/`) общая для всех услуг, поэтому:

- чтобы поменять текст, цену, срок, этапы, FAQ или список кейсов — правьте только данные;
- чтобы добавить новую услугу — добавьте объект в массив `SERVICES`. Страница, пункт в
  подвале, карточка на `/services`, запись в `sitemap.xml` и статическая HTML-страница
  появятся автоматически.

Цены и сроки в данных — те же, что были на сайте раньше. Новые цифры не выдумывались:
если стоимость индивидуальная, об этом сказано в поле `priceNote`.

## Заявки и персональные данные

- Все формы отправляют заявку через `src/lib/leads.ts` — там же лежит адрес приёмника
  (Google Apps Script). Чтобы перевести заявки на свой backend, достаточно поменять
  константу `LEADS_ENDPOINT`.
- Формы шлют поля: `formType`, `service`, `name`, `phone`, `contact`, `comment`,
  `consent`, `date`, `utm`, `pageUrl`. **Если приёмник — таблица, добавьте в неё новые
  колонки** (`service`, `phone`, `comment`, `consent`), иначе часть данных потеряется.
- Согласие на обработку персональных данных (`src/components/ConsentCheckbox/`) стоит во
  всех формах: на страницах услуг, на `/contact` и в калькуляторе на главной. Галочка
  никогда не отмечена заранее, без неё форма не отправляется, а факт согласия уходит
  в заявку вместе с текстом формулировки.
- Текст согласия и страница `/privacy` — **рабочий шаблон, а не юридический документ.**
  Замените формулировки на согласованные с юристом: константа `CONSENT_TEXT` в
  `ConsentCheckbox.tsx` и текст в `src/pages/Privacy/PrivacyPage.tsx` (места для
  заполнения выделены пунктиром прямо на странице).

## SEO

Что уже сделано:

- уникальные `title` и `description` на каждой странице (компонент `src/components/Seo/`);
- один `H1` на страницу и осмысленная структура `H2`/`H3`;
- `canonical`, Open Graph и Twitter-теги;
- микроразметка schema.org: `Organization`, `WebSite`, `Service`, `FAQPage`,
  `BreadcrumbList`, `ItemList`, `CreativeWork`;
- хлебные крошки и перелинковка между услугами, кейсами и подвалом;
- `public/robots.txt` с `Sitemap`, `Host` и `Clean-param` для UTM-меток;
- `dist/sitemap.xml` — генерируется при сборке, служебные страницы (`/thanks`, `/privacy`)
  в него не попадают и закрыты `noindex`;
- **пререндер** (`scripts/prerender.mjs`): после `vite build` для каждого адреса создаётся
  статический HTML с уже подставленными мета-тегами, микроразметкой и текстовым слепком
  страницы в `<noscript>`. Это нужно, потому что сайт — SPA: без пререндера робот, который
  не выполняет JavaScript (а Яндекс делает это не всегда), видел бы на всех адресах
  одинаковый пустой `index.html`.

Что нужно сделать после деплоя:

1. Подтвердить сайт в [Google Search Console](https://search.google.com/search-console) и
   [Яндекс Вебмастере](https://webmaster.yandex.ru). Заготовки мета-тегов подтверждения
   лежат закомментированными в `index.html` — раскомментируйте нужную и вставьте код.
2. В обеих панелях добавить карту сайта: `https://avoralab.ru/sitemap.xml`.
3. В Яндекс Вебмастере проверить, что раздел «Переобход страниц» видит адреса услуг.

Тексты написаны для людей: ключевые запросы (`keywords` в `services.ts`) использованы
естественно, переспама нет.
